# 間取り図 (家電の場所)

家の間取りを 2D の平面図で表示して、場所が決まっている製品 (エアコン・給湯器・換気扇・冷蔵庫など) を点で示す機能。画面は「間取り」(`/map`) と「間取り設定」(`/map/settings`)。背景は [ADR 0010](adr/0010-home-map-layout-json-in-d1.md) と Issue #61。

## 家族での共有

間取りは家族で 1 枚を共有する。Cloudflare Access を通った家族全員が同じ共有ユーザー ID (`APP_USER_ID`) を使うので (ADR 0005)、`home_layouts` はその ID ごとに 1 行になる。夫婦のどちらが保存しても、もう一方の画面にも同じ間取りが出る。保存し直すと前の間取りは置き換わる (後から保存した方が残る)。

## 間取りを登録する流れ

1. 「間取り設定」で **AI への指示をコピー** を押す (指示の本文は `src/features/home-map/layout-prompt.ts`)。
2. Claude や ChatGPT に、賃貸の間取り図の画像 (不動産サイトの図面や写真) と、コピーした指示を送る。
3. 返ってきた JSON を「間取りの JSON」に貼り付ける。` ```json ` の囲みが付いたままでも読める。
4. その場で書式を確かめ、誤りがあれば場所 (例: `rooms[2].type`) とともに表示する。正しければプレビューが出るので、見た目を確かめて **保存** する。

部屋の大きさや向きが違っていたら、JSON を手で直すか、AI に「洋室をもう少し広く」「玄関ドアは外開き」のように頼んで作り直してもらう。「サンプルを入れる」で架空の 2DK の例を入れられる。

本物の間取りは git に入れない (D1 にだけ保存する)。リポジトリにあるのは書式 (zod スキーマ) と、テスト・E2E 用の架空の間取り (`src/features/home-map/sample-layout.ts`) だけ。

## JSON の書式 (version 1)

単位は cm。左上が原点で、x は右、y は下に増える。座標はすべて 0 以上 10000 以下。定義は `src/domain/home-map/home-layout.ts` の `HomeLayoutSchema`。

```json
{
  "version": 1,
  "name": "2DK のアパート",
  "rooms": [
    { "id": "dk", "name": "DK", "type": "dining", "rect": [0, 0, 360, 300] },
    { "id": "bedroom", "name": "洋室", "type": "bedroom", "rect": [360, 0, 300, 300] },
    {
      "id": "closet",
      "name": "収納",
      "type": "storage",
      "polygon": [
        [0, 300],
        [90, 300],
        [90, 460],
        [0, 460]
      ]
    }
  ],
  "doors": [
    { "wall": [360, 120, 360, 200], "hinge": "start", "opensInto": "bedroom" },
    { "wall": [0, 300, 80, 300], "kind": "sliding" }
  ],
  "windows": [{ "wall": [400, 0, 600, 0] }]
}
```

| 項目                | 必須 | 内容                                                                                                                                                  |
| ------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`           | ○    | いまは `1` だけ                                                                                                                                       |
| `name`              |      | 間取りの名前 (40 文字以内)。画面の見出しの下に出る                                                                                                    |
| `rooms[].id`        | ○    | 英小文字・数字・`_`・`-` の 40 文字以内。重ならないこと                                                                                               |
| `rooms[].name`      | ○    | 図に出す部屋名                                                                                                                                        |
| `rooms[].type`      | ○    | `living` `dining` `kitchen` `bedroom` `japanese` `toilet` `bath` `washroom` `entrance` `hallway` `storage` `balcony` `other` のどれか。床の色が変わる |
| `rooms[].rect`      | ※    | 長方形の部屋 `[x, y, 幅, 奥行き]`                                                                                                                     |
| `rooms[].polygon`   | ※    | L 字などの部屋。角の座標 `[[x, y], ...]` を順番に 3〜40 個                                                                                            |
| `rooms[].labelAt`   |      | 部屋名を出す位置 `[x, y]`。省略すると図形の中心 (L 字で中心が外に出るときに書く)                                                                      |
| `doors[].wall`      | ○    | 開口部の両端 `[x1, y1, x2, y2]`                                                                                                                       |
| `doors[].kind`      |      | `hinged` (開き戸、省略時) か `sliding` (引き戸・襖)                                                                                                   |
| `doors[].hinge`     |      | 開き戸の蝶番が `wall` の始点側 (`start`、省略時) か終点側 (`end`) か                                                                                  |
| `doors[].opensInto` |      | 開き戸が開く先の部屋の `id`。家の外へ開くなら `outside`。省略すると `wall` の進む向きの左側へ開く                                                     |
| `windows[].wall`    | ○    | 窓の両端 `[x1, y1, x2, y2]`                                                                                                                           |

※ `rect` と `polygon` はどちらか一方だけ書く。書式にない項目があるとエラーにする (書き間違いに気づけるように)。部屋は 60 個、ドア・窓は 100 個、JSON は 50,000 文字まで。

### 書式を変えるとき

- 項目を足すだけなら `version` は 1 のまま、任意項目として足す。保存済みの JSON は読み込み時にもスキーマで確かめるので、必須項目を足したり意味を変えたりするときは `version: 2` を作り、1 からの変換を書く。
- `HomeLayoutSchema`・AI への指示 (`layout-prompt.ts`)・この文書の 3 つをそろえて直す。

## データ

| テーブル       | 中身                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------- |
| `home_layouts` | `user_id` (主キー、家族の共有 ID)・`layout_json` (スキーマで確かめた JSON)・`updated_at` |

どの部屋に何があるかは保存しない。点の座標と部屋の形から、表示するときに計算する (`findRoomAt`)。

## マイグレーション

`home_layouts` を足したので、手元では `vp run db:migrate` を実行する。本番はリリースの CD (`db:migrate:remote` → デプロイ) で適用される。
