# 実装計画: 「今やること」トップページ・カレンダー表示・スキップ

2026-09-26 にユーザーから挙がった 3 つの改善をまとめた計画。いずれもドメイン層・ユースケース層・画面の変更で、Cloudflare への移行（[cloudflare-migration.md](./cloudflare-migration.md)）とは独立して進められる。

用語は [CONTEXT.md](../../CONTEXT.md)、スキップの考え方は [ADR 0006](../adr/0006-skip-advances-to-next-cycle-and-is-logged.md) を参照。

## 進める順番

1. **スキップ**（データの変更を伴うので最初に入れる。トップページとカレンダーがこれを表示に使う）
2. **「今やること」トップページ**
3. **カレンダー表示**

各ステップで `vp check` と `vp test` を通し、`vp dev` で画面を確認する。1 ステップ 1 PR を目安にする。

## 1. スキップ（先送り）

> 2026-09-26 実装済み。スキップの取り消しと履歴一覧は「後から足せるもの」のまま。

### できるようになること

- タスクに「スキップ」ボタンが付く。押すと、その回はやらずに次の周期へ先送りされる。
- タスクに「〇回スキップ中」「最終実施 〇/〇（〇日前）」が表示され、どれだけ放置しているかがわかる。
- 完了するとスキップ回数は 0 に戻る。

### 仕様

- 次回予定日 = スキップした日 + interval（ADR 0006）。`last_done_at` は変えない。
- interval が未設定のタスクではボタンを出さない。
- 押したときは確認ダイアログで「次回は 〇/〇 になります」と先に見せる。メモは任意で残せる（「まだ汚れていない」など）。
- スキップ回数 = `last_done_at` より後にある `skipped` ログの件数。一度も完了していないタスクは全ログが対象。

### 変更箇所

| 層                     | 変更                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DB                     | `maintenance_logs` に `kind`（`'done' \| 'skipped'`、既定 `'done'`）を追加し、`done_at` は「記録した日」として両方で使う。Drizzle でマイグレーション生成 |
| domain                 | `MaintenanceLog` に `kind` を追加。`countSkipsSinceLastDone(logs, lastDoneAt)` のような純粋関数を置き、単体テストを書く                                  |
| usecase                | `skipMaintenance`（新規）: ログ追加 + `next_due_date` 再計算。`markMaintenanceDone` は `kind: 'done'` を明示                                             |
| repository             | タスクごとのスキップ回数をまとめて取れる集計（一覧画面で N+1 にしない）                                                                                  |
| server function / 画面 | `/maintenance`・製品詳細・トップページにスキップボタンと「〇回スキップ中」バッジ                                                                         |

### 後から足せるもの

- 直前のスキップの取り消し。
- 実施・スキップの履歴一覧（製品詳細のタスク行を開くと出る）。
- 「3回以上スキップしているタスク」を目立たせる、または周期の見直しを促す表示。

## 2. 「今やること」トップページ

> 2026-09-27 実装済み。「今日」をブラウザのタイムゾーンで決めるため、このページは `ssr: "data-only"`（データだけサーバーで取得し、画面はブラウザで描く）にした。Workers は UTC で動くので、他の画面も同じ問題を抱えている（日本時間の 0〜9 時に 1 日ずれる）。

### できるようになること

- アプリを開くと、今対応すべきタスクだけが短く並ぶ。全件一覧は今の `/maintenance` に残す。
- その場で「完了」「スキップ」を押せる。

### 仕様

- 表示するもの: **期限超過** と **今日から 7 日以内** のタスクだけ。期限の近い順。
- 1 行に「製品名 ・ タスク名 ・ 期限（あと〇日 / 〇日超過）」と、あればスキップ回数を出す。
- 何もないときは「今やることはありません」と、次に来るタスク 1 件（「次は 〇/〇 エアコン フィルター清掃」）を出す。
- 画面下に「すべてのメンテナンス」「カレンダー」へのリンク。
- スマホで片手操作しやすいよう、カード型で完了・スキップボタンを大きめにする。

### 変更箇所

- `src/routes/index.tsx`: `/maintenance` へのリダイレクトをやめ、トップページを実装する。
- 期限の分類（期限超過 / 今週 / 来月まで…）は今 `maintenance.tsx` の中にあるので、domain の純粋関数（例: `classifyByDueDate(tasks, today)`）に切り出して両画面で使い、テストを書く。
- 「7 日以内」の日数は定数にしておく（後で設定にできるように）。

## 3. カレンダー表示

### できるようになること

- 月のカレンダーで、どの日にどのメンテナンスの予定があるかが見える。
- 過去の日には、実施した記録とスキップした記録も出る。

### 仕様

- 新しい画面 `/calendar`。Mantine の `@mantine/dates`（導入済み）の月表示を使い、日付セルに件数のバッジを出す。
- 日付を押すと、その日の予定・実施・スキップの一覧が下に出る（スマホでもセルに文字を詰め込まない）。
- 表示するもの:
  - **予定**: 各タスクの `next_due_date`。期限超過のものは今日のセルにまとめて赤で出す。
  - **実施 / スキップ**: `maintenance_logs` の記録日。
  - **目安（任意・薄く表示）**: 3 か月先までは「次回予定 + interval の繰り返し」を目安として薄く出す。ADR 0001 のとおり実データとしては保存せず、表示のためだけに計算する。
- 製品やカテゴリでの絞り込みは後から。

### 変更箇所

- domain: 指定月の表示用イベントを組み立てる純粋関数（予定・目安・記録）とテスト。
- usecase / server function: 期間を指定してログを取得する（`listMaintenanceLogs({ from, to })`）。
- route: `src/routes/calendar.tsx`、ナビゲーションにリンク追加。

### 後から足せるもの: Google カレンダーなどへの購読（iCal）

- `/api/calendar.ics` で予定を iCal 形式で配信すれば、Google カレンダーやスマホのカレンダーに表示でき、通知もそちらに任せられる。
- ただし本番は Cloudflare Access の後ろにあるため、カレンダーアプリからは取得できない。Access でこのパスだけ Bypass にし、URL に推測できないトークンを付けて守る設計が必要。本番化（cloudflare-migration.md）が済んでから検討する。
