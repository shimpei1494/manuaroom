# 消耗品は独立エンティティではなく Maintenance Task として扱う

「フィルター交換 / 6ヶ月ごと」のような消耗品交換は、独立した `consumables` テーブルではなく `maintenance_tasks` テーブルに通常のタスクとして登録する。AI Suggestion の type も `"maintenance"` 一本に統一し、消耗品サブタイプは作らない。

理由：データ構造として「対象 + 周期 + ページ番号」が完全に同じで、テーブル分割すると重複コード・UI が増える。MVP では「いつ交換すべきか」を知れれば十分。部品名・型番管理・購入リンクは `memo` と単一 `url` フィールドで吸収する。将来「フィルターの型番だけ別管理したい」等の要望が固まったら、`maintenance_tasks` から消耗品レコードを `consumables` に分離するマイグレーションを行う。
