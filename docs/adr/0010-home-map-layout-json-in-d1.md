# 間取りは JSON を D1 に 1 行で保存し、SVG で描く

家の間取り図 (Issue #61) は、間取りを JSON (単位 cm、左上が原点) で表し、D1 の `home_layouts` に家族で 1 行だけ保存する。画面では JSON から SVG の平面図を組み立て、部屋名と家電の点は HTML で重ねる。間取りの JSON は、間取り図の画像を AI に渡して作ってもらい、「間取り設定」に貼り付けて登録する。

理由：今の家は賃貸の 2DK の平屋で、立体の家具まで再現する 3D (three.js) は作る手間・模様替えのたびに直す手間・バンドルの増加に見合わない。2D の平面図なら追加のライブラリなしで SSR でも描け、JSON は数 KB なので D1 の 1 行で足りる。Access の内側にあるので家族以外には見えず、git に家の間取りを入れずに済む。

## 決めたこと

- **家族で共有する。** 他のデータと同じく共有のユーザー ID (ADR 0005) をキーにする。Household を導入するとき (ADR 0004) は、他のテーブルと一緒に `household_id` に置き換える。
- **書式は zod のスキーマ (`HomeLayoutSchema`) で 1 か所に定義する。** 型・貼り付け時の検証・保存済みデータの読み込みに同じものを使う。domain に置くが、zod は外側の層ではないので ADR 0007 の依存の向きは崩れない。
- **書かれていない項目はエラーにする (strict)。** AI が勝手に項目を足したり、`rect` を `rectangle` と書き間違えたりしたときに、黙って無視せず気づけるようにする。
- **文字と点は HTML で重ねる。** SVG の文字は図の縮尺に合わせて伸び縮みするので、スマホでは小さすぎ、PC では大きすぎる。座標を割合 (%) にして HTML を重ねれば、大きさは一定で、Mantine の Popover もそのまま使える。線の太さは `vector-effect: non-scaling-stroke` で一定にする。
- **拡大・移動は入れない。** 2DK なら画面幅に収まる。

## 不採用案

- **3D (three.js)**: 上の理由。間取りが変わる引っ越し先が戸建てになったら考え直す。
- **間取りの JSON を git に入れる / R2 に置く**: git は家の間取りを残したくない。R2 はアップロードの仕組みが要り、手順が増える。
- **間取り図の画像をそのまま背景に敷く**: 手軽だが、不動産の図面は文字や寸法線が多く点が見づらい。ダークモードにも合わない。
