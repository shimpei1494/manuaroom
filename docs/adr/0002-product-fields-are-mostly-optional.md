# Product フィールドはほぼすべて任意

`products` テーブルで必須なのは `name` のみ。`manufacturer` / `model_number` / `category` / `location` / `purchase_date` / `warranty_until` / `memo` はすべて任意（NULL 許容）で、UI 設計でも「ユーザーは入力しない前提」で進める。

理由：個人ユースでは、手元の家電・家具で「メーカー不明」「型番が読めない」ものは普通にある。入力ハードルを下げて登録自体を完了させる体験を優先する。詳細情報は将来 AI が PDF から自動抽出して提案する想定（A フロー、未実装）なので、ユーザーが手入力でこれらを埋めるコストは積極的に避ける。

## 影響

- フォーム UI: `name` 以外は折りたたみ・スキップしやすい配置にする
- 一覧表示: 空欄前提でレイアウトを組む
- 検索・フィルタ: これらのフィールドが空のレコードでも見つけられる UX が必要
- AI 機能の優先度: メタデータ抽出（A フロー）は MVP 後の高優先機能
