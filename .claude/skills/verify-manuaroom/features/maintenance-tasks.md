# メンテナンスタスク

製品を登録し、その製品に周期つきのメンテナンスタスクを追加できる。「今やること」から完了を記録すると、次回予定日が完了日 + 周期に立て直され (ADR 0001)、通知の「元に戻す」で取り消せる。

## Sub-features

- `product-create` 製品名だけで製品を登録する (ほかの項目は任意、ADR 0002)。
- `task-create` 製品の詳細画面でタスク名と周期 (値 + 単位) を指定して追加する。
- `tasks-today` 「今やること」に期限が近いタスクが `あとN日` つきで出る。
- `tasks-complete` 完了を記録し、次回予定日を完了日 + 周期にする。
- `tasks-undo` 完了の通知から元に戻す。

## How to get to it (user POV)

- ナビの `製品` (PC 幅は左のサイドバー、スマホ幅は画面下のタブバー) → 製品一覧 (カードの並び) → `新規登録` (`/products/new`) で `製品名` を入れて Enter (スマホ幅では開発用 Devtools のボタンが `登録` に重なるため。画面には「説明書 PDF から登録」のボタンもある)。
- 製品名のリンクから詳細 (`/products/<id>`) を開き、`タスクを追加`。
- ナビの `今やること` (`/`) の「今やること」のカードにある `完了`。
- 製品詳細のタスク表 (`row`) にある `完了`。
- ナビの `メンテナンス` (`/maintenance`。スマホ幅のタブバーでは `メンテ`) の一覧。

## Driving it with drive.mjs

Preconditions:

- `scripts/doctor.sh` が `FAIL` なし。
- 製品はまだ無くてよい (journey が自分で作る)。

- **製品を作る。** `node .claude/skills/verify-manuaroom/scripts/drive.mjs tasks`。`製品名` に `検証製品 <8 桁>` を入れて Enter を押し、製品名のリンクを開く。製品名の見出しが出る。
- **タスクを追加する。** `タスクを追加` → ダイアログで `タスク名` に `フィルター掃除`、`周期` に `3`、`単位` を `日` にして `追加`。`タスクを追加しました` が出る。
- **今やることを見る。** `/` を開く。製品名を含むカードに `フィルター掃除` と `あと3日` が出る。証拠: `tasks-1-today.png`。
- **完了する。** カードの `完了` を押す。`完了を記録しました` の通知が出て、カードは `あと3日` のまま残る (次回が今日 + 3 日)。証拠: `tasks-2-done.png`。
- **元に戻す。** 通知の `元に戻す` を押す。`取り消しました` が出る。証拠: `tasks-3-undone.png`。
- **画面の外で確かめる。** `select title, next_due_date, last_done_at from maintenance_tasks` と `select kind, done_at from maintenance_logs` (SKILL.md の `wrangler d1 execute`)。完了のあとはログが 1 行増え、取り消しのあとは減る。

## Gotchas

- 通知は数秒で消える。`完了を記録しました` の確認と `元に戻す` は続けて行う。
- 今日の日付は日本時間 (`Asia/Tokyo`) で見る。ブラウザの時間帯が違うと `あとN日` がずれる。
- `完了` と `完了を記録しました` は別物。ボタンの検索は `getByRole("button", { name: "完了" })` のように、カード・行の中に絞る。
- 未確認: 製品の任意項目 (メーカー・型番など) の入力、タスクの編集・削除、`メンテナンス` (`/maintenance`) 一覧からの完了。journey は `/` と製品詳細からの操作だけを通す。
